## O contador que some
 
A implementação ingênua de rate limiting
guarda um `Map` em memória: chave é o IP,
valor é a contagem na janela.
 
Em execução serverless, não existe "o
processo". Cada requisição pode cair em
uma instância diferente.
 
> O código está sintaticamente correto,
> os testes passam, o deploy sobe — e a
> proteção não existe.
 
## Store compartilhado sem Redis
 
O PostgreSQL que já está no projeto
resolve, com uma tabela e um upsert:
 
```sql
INSERT INTO rate_limit_counter
(key, window_start, hits)
VALUES ($1, $2, 1)
ON CONFLICT (key, window_start)
DO UPDATE SET hits = ... + 1;
```
 
O incremento é atômico por construção.
